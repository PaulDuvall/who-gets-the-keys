On 2026-11-15 the owner rolled `main` back from `7bf87a9` to `aedf88a` with a force push. The owner asked for the rollback, and a Claude Code session gave the steps. To allow the force push, the `protect main` ruleset was changed for 16 minutes. Afterwards, the replaced commit's four workflow runs were deleted.

The hand-off note recorded only "`main` moved to `aedf88a`" (`docs/notes/owner-queue-handoff-2026-11-13.md`, row S-2). This note records the rest, so the force push and the gaps in the run numbers have an explanation in the repository.

## Why it is recorded

On 2026-11-18 the agent checked this repository against the wfx campaign. Since 2026-11-10 that campaign has used stolen GitHub tokens to push a CI secret stealer, revert it, and delete the workflow run and its logs (OX Security, https://www.ox.security/blog/thousands-of-github-accounts-hijacked-with-wfx-loot-ci-secret-stealing-malware-via-github-actions-npm/; StepSecurity, https://www.stepsecurity.io/blog/wfx-phantom-the-github-actions-secret-stealer; both read 2026-11-18).

The check found none of the campaign's indicators. It did find four missing run numbers, and a force push to `main` that today's history no longer shows. Until the owner confirmed the rollback, those looked like the campaign's tell. The agent had first said that `main` only grows and received no push in that window; both statements were wrong, because they came from reading today's history.
